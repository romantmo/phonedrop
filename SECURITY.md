# Безопасность PhoneDrop

Простыми словами: что защищено, от чего и как.

## Как устроен доступ

Как в WhatsApp Web: **телефон — это аккаунт**, а компьютеры к нему подключаются по QR-коду.

| Кто | Чем доказывает, что это он | Где хранится |
|---|---|---|
| Телефон | Секретный ключ (256 бит) | Cookie `pd_phone`: HttpOnly, SameSite=Lax, Secure, 1 год |
| Компьютер ⏳ «временный» | Свой секретный ключ (256 бит) | Cookie `pd_pc`: HttpOnly, SameSite=Strict, Secure. Живёт, пока открыт браузер |
| Компьютер 🔒 «постоянный» | Тот же ключ | Та же cookie, но на 90 дней (продлевается при каждом заходе) |
| QR-код | Одноразовый код подключения | Сгорает после сканирования, обновления страницы или через 5 минут |
| Собеседник в «чате с человеком» | Свой секретный ключ (256 бит), выдаётся при входе по коду | Cookie `pd_rg`: HttpOnly, SameSite=Lax, Secure, 1 год. Даёт доступ только к чатам, куда вошли по коду |
| Код приглашения в чат | 9 цифр или ссылка `/j/<ключ>` | Одноразовые, живут 24 часа; в базе — только HMAC-отпечаток. Новый код — после входа по нему старый гость отключается |

- На сервере хранятся **только хэши** ключей (SHA-256). Даже если базу украдут, войти по ней нельзя.
- Секреты не попадают в адресную строку. Одноразовый код сразу убирается из адреса и становится бесполезным.
- Каждый компьютер видит **только свой** чат с телефоном. Рабочий ноутбук не видит переписку домашнего ПК.

## Хранение данных

| Что | Сколько хранится |
|---|---|
| Переписка с «чужим» компьютером | Удаляется через минуту после закрытия вкладки |
| Переписка с «моим» компьютером | Пока компьютер подключён |
| Файлы, фото, видео, голосовые | 30 дней (`FILE_TTL_DAYS`), потом удаляются. Текст сообщений остаётся |
| «Мой» компьютер, на который не заходили | Отключается через 90 дней (`REMEMBER_DAYS`) |
| Результаты «Инструментов» (сканы, PDF, сжатые фото) | 30 минут (`TOOL_TTL_MIN`), видны только тому, кто их сделал |
| Передачи между своими компьютерами | До 24 часов (`TRANSFER_TTL_HOURS`), недокачанные — тоже. Видны только отправителю и получателю |
| Фото страниц в сканере | 30 минут с последнего действия, видны только своему телефону/компьютеру |
| Превью Word/Excel/PowerPoint | Пока лежит сам документ, удаляется вместе с ним |
| Чат с человеком: текст | Пока создатель не закроет чат (или 30 дней без сообщений — `ROOM_IDLE_DAYS`) |
| Чат с человеком: фото, голосовые, файлы | 24 часа (`TRANSFER_TTL_HOURS`), недокачанные — тоже. Видят только двое участников |

Отключить любой компьютер можно в любой момент: на самом компьютере или с телефона (меню чата → «Отключить»). Вместе с ним удаляются переписка и файлы.

## От чего защищено

| Угроза | Пример | Защита |
|---|---|---|
| Кто-то сфотографировал QR-код | Коллега за спиной | Код одноразовый и живёт 5 минут. Новый компьютер виден в списке на телефоне |
| Забыл выйти на чужом компьютере | Ушёл от клиента, вкладка открыта | Режим «временный» по умолчанию + отключение компьютера с телефона |
| Подслушать звонок | Кто-то в той же сети или на сервере | Звук и видео шифруются браузерами (DTLS-SRTP). Сервер передаёт только «рукопожатие», TURN пересылает зашифрованные пакеты и расшифровать их не может |
| Воспользоваться нашим TURN-сервером | Чужие гоняют через него свой трафик | Вход только по временному ключу (12 ч), который выдаётся участникам чатов. Лимиты на число сессий и скорость. `--no-tcp-relay`: TCP-соединения к чужим серверам TURN не открывает — как прокси его не использовать |
| Через TURN залезть внутрь сервера | Запрос к 127.0.0.1 или в сети Docker | `denied-peer-ip`: внутренние и служебные адреса запрещены, включая IPv4-внутри-IPv6 (CVE-2026-27624); coturn ≥ 4.9, без прав root, только чтение |
| Пароль от PDF утечёт | Пароль для «Пароль на PDF» попадёт в логи или базу | Пароль уходит только конвертеру внутри сервера, нигде не сохраняется и не пишется в журнал; шифрование AES-256 |
| Чужой воспользуется подписью | Подпись осталась на чужом компьютере | Подпись хранится только в браузере устройства; на компьютере по умолчанию не запоминается; в PDF ставится только туда, куда человек сам её перетащил |
| Позвонить чужому | Посторонний знает адрес чата | Звонить и отвечать могут только двое участников чата; на чужие звонки — 404 |
| Перебор адресов чатов и файлов | Скрипт подбирает ссылки | Длинные случайные id (122–256 бит). Файл отдаётся только участникам своего чата |
| Вредный сайт шлёт запросы от твоего имени (CSRF) | Открыл ссылку, а она пишет в твой чат | Проверка `Origin`, обязательный заголовок `X-PD-Role`, SameSite-cookie |
| Скрипт в сообщении (XSS) | Прислали `<script>…</script>` | Текст выводится только как текст + строгая Content-Security-Policy |
| Опасный файл открывается в браузере | `evil.html` или `.svg` со скриптом | Такие файлы только скачиваются, плюс `CSP: sandbox` и `nosniff` |
| Имя файла `../../etc/passwd` | Попытка записать в системную папку | На диске файл лежит под случайным id, имя — только для показа |
| Встраивание в чужую страницу (clickjacking) | Невидимая рамка поверх кнопок | `X-Frame-Options: DENY`, `frame-ancestors 'none'` |
| Следы на чужом компьютере | Картинки в кэше браузера | `Cache-Control: no-store` |
| Переполнение диска | Загрузка гигабайтов мусора | Лимит 500 МБ на отправку, 4 ГБ на чат, проверка свободного места, срок хранения файлов |
| Спам | Скрипт создаёт тысячи подключений | Ограничение частоты по IP и по аккаунту |
| Вредный документ или «бомба» в фото | Word с эксплойтом, PNG на миллиард пикселей | Конвертер — отдельный контейнер: только внутренняя сеть без интернета, нет доступа к базе и файлам чатов, файловая система только для чтения, лимиты памяти/CPU/процессов, каждая операция — в отдельном процессе, который убивается через 3 минуты (LibreOffice — через 2), проверка размера картинки до распаковки; результат конвертации — не больше 1 ГБ |
| PDF во встроенном просмотрщике | PDF со скриптом | PDF отдаётся без песочницы (иначе Chrome его не покажет), но с точным типом и `nosniff`: страницей сайта он стать не может, а скрипты PDF браузер выполняет отдельно от сайта |
| Чужие используют конвертер | Бесплатная «перегонка» файлов | Инструменты работают только для подключённого телефона или компьютера, ограничение частоты и размера (100 МБ) |
| Геолокация в фото | GPS в EXIF | «Сжать фото» удаляет все метаданные |
| Чужой забирает чаты через «Переподключить телефон» | Коллега подходит к твоему компьютеру | Кнопка есть только у «Моего компьютера», код одноразовый на 5 минут. Старый телефон сразу отключается и получает уведомление «чаты открыты на другом телефоне» — переподключиться обратно можно с любого своего компьютера |
| Чужой «забирает» переписку компьютера | Подставляет свой QR в «Переподключить компьютер» | Действие делает только телефон-владелец чата; ключ переносится на браузер, который показал QR, старый вход перестаёт работать |
| Подбор кода приглашения в чат | Скрипт перебирает коды на /get | 9 цифр (миллиард вариантов), 10 попыток за 10 минут с адреса и общий предел на всех; код одноразовый и живёт не дольше суток |
| Чужой в «чате с человеком» | Кто-то подсмотрел код или ссылку | Код сгорает при первом входе. Создатель видит «вошёл в чат»; если вошёл не тот — «Код приглашения» → новый код, и после входа по нему чужой отключается. Удалять можно только свои сообщения, закрыть чат — только создатель |
| Превью ссылки «съедает» приглашение | WhatsApp/Telegram открывают ссылку для превью | Страница `/j/<ключ>` ничего не тратит — вход только кнопкой (POST) |
| Утечка базы с ссылками и кодами | Кража `phonedrop.db` | Хранятся только HMAC-отпечатки ссылок и кодов (секрет — в отдельном файле `secret.key`) |
| Ссылка-приглашение утекла | Переслали не тому | Ссылка одноразовая; «Код приглашения» в меню чата выдаёт новый, и после входа по нему старый вход отключается; `Referrer-Policy: no-referrer` |
| Переполнение диска большими файлами | 10 ГБ × много | Лимит 10 ГБ на файл и 20 ГБ на владельца, проверка свободного места с учётом незаконченных загрузок, автоудаление |
| Чужой заводит аккаунт на сервере | Открыл сайт и отсканировал QR своим телефоном | С включённым входом через Google новый телефон должен войти разрешённым аккаунтом: админы — из `ALLOWED_EMAILS` на сервере, остальных добавляет админ |
| Пользователь сам раздаёт доступ | Мама добавляет кого-то ещё | Список пользователей видит и меняет только админ (адрес из `.env`). Админа нельзя убрать из приложения |
| Доступ нужно закрыть срочно | Потерян телефон, уволился сотрудник | «👥 Пользователи» → «Убрать»: выход на всех устройствах сразу, его чаты и файлы удаляются; каждый запрос заново проверяет, есть ли адрес в списке |
| Гость нагружает сервер инструментами | Собеседник по коду запускает конвертер без остановки | Инструменты доступны только тому, кто вошёл в чат по коду; лимит запусков в минуту и размер файла — как у всех |
| Подделка входа через Google | Подставной ответ, перехват кода | OpenID Connect: state (защита от CSRF) в подписанной cookie, PKCE, nonce, проверка iss/aud/exp/email_verified; токен берём напрямую у Google по HTTPS |
| Утечка ключа Google | Секрет в коде или GitHub | Ключ и секрет лежат только в `/opt/phonedrop/.env` на сервере (права 600) |
| Запрос файлов используют для чужих целей | Кто-то узнал код запроса | Код даёт только право загрузить тебе в пределах лимита и срока; скачать и увидеть файлы по нему нельзя; запрос можно закрыть |
| Через «Проверку портов» залезть внутрь (SSRF) | Проверить 127.0.0.1, сети Docker, 169.254.169.254 (метаданные облака) | Все адреса имени проверяются: внутренние, служебные, IPv4-внутри-IPv6 — отказ. Подключение идёт к уже проверенному IP (подмена DNS между проверкой и подключением не поможет) |
| Сканер портов «за наш счёт» | Перебор портов чужого сервера | Только пользователи с аккаунтом (не гости), до 10 портов за раз, 60 проверок за 10 минут, 30 запросов в минуту |
| Утечка пароля из одноразовой ссылки | Кража базы, логи сервера | Текст шифруется в браузере (AES-256-GCM), ключ — в части ссылки после «#», которая на сервер не отправляется. После открытия шифровка стирается; просроченные удаляются |
| Превью мессенджера «сжигает» одноразовую ссылку | Telegram открывает ссылку для превью | Страница `/k/<id>` ничего не раскрывает — открытие только кнопкой (POST); ключ убирается из адресной строки |
| Пароль Wi-Fi остаётся на сервере | QR-код для Wi-Fi | Сервер только рисует картинку и ничего не сохраняет; пароли, подсети и заголовки писем обрабатываются в браузере |
| Через «Проверку ссылки» залезть внутрь | Ссылка перенаправляет на 127.0.0.1 или 169.254.169.254 | Каждая переадресация проверяется заново: внутренние адреса — стоп. Подключение к проверенному IP (имя только в заголовке и SNI) |
| Вредная страница при проверке ссылки | Скрипт на фишинговом сайте | Сервер читает только заголовки и начало HTML (до 256 КБ), ничего не выполняет; в приложении ссылки из писем не кликабельные |
| Вирус в письме попадёт на сервер | Проверка письма с вложением-вирусом | Письмо разбирается в памяти и не сохраняется; вложения не распаковываются и не открываются — только байты для антивируса и sha256. Антивирус ClamAV — отдельный контейнер, порт наружу закрыт, память ограничена |
| Утечка файлов и токенов в VirusTotal | Вложения клиента или ссылка сброса пароля попадут в VirusTotal | Файлы туда не уходят — только «отпечаток» sha256. Ссылку VirusTotal ищет по адресу **без** `?параметров` и `#якоря` (в них бывают токены); отправить на новую проверку — только кнопкой с предупреждением. Ключ `VT_API_KEY` — только в `.env` |
| Ключ GitHub-робота украли | Атакующий выкатывает старую версию или коммит из форка | Ключ умеет только запускать `deploy.sh`, а тот выкатывает **только последний коммит main** (сверка с GitHub). Действия в CI закреплены по SHA коммита. Если новая версия не поднялась — `deploy.sh` сам возвращает прежнюю |
| Ключи Google пропали из `.env` | Регистрация незаметно открывается всем | `REQUIRE_LOGIN=1`: без `GOOGLE_*` и `ALLOWED_EMAILS` приложение не запускается («закрытый» отказ) |
| Сервер шлёт запросы куда скажут | Поддельная push-подписка на чужой адрес | Push-уведомления — только на адреса push-сервисов браузеров (Google, Mozilla, Apple, Microsoft) |
| Проверить свой сервер в обход файрвола | Проверка портов на 2.31.111.188 изнутри | Адреса самого сервера (`NET_BLOCK_IPS`) и IPv4, спрятанный в IPv6 (`64:ff9b::/96`, `::/96`), запрещены в сетевых инструментах |
| Один контейнер съест всю память | Сбой или атака на приложение | Лимиты памяти у всех контейнеров (app 1 ГБ, caddy 256 МБ, конвертер 1,5 ГБ, ClamAV 2 ГБ) + swap 2 ГБ |
| Журналы забьют диск, в них коды из адресов | Месяцы работы без ротации | Журналы Docker: не больше 5 файлов по 10 МБ на контейнер |
| Поддельные push-уведомления | Кто-то шлёт уведомления от имени сайта | Уведомления подписаны ключом VAPID сервера, содержимое шифруется для браузера |

## Что делается на сервере (при деплое)

- **HTTPS** с автоматическим сертификатом Let's Encrypt (Caddy) + HSTS.
- **Firewall** Hetzner: открыты только порты 22, 80, 443 и для звонков — 3478 (TCP и UDP) и 49160–49200 (UDP).
- Вход по SSH только по ключу, без паролей (`/etc/ssh/sshd_config.d/00-hardening.conf`, проверено 14.11.2026).
- Подкачка (swap) 2 ГБ, `vm.swappiness=10` — чтобы при нехватке памяти система не «убивала» процессы.
- Приложение в Docker-контейнере от обычного пользователя (не root), данные — в отдельном томе.
- Автоматические обновления безопасности Ubuntu.

## Чего пока нет (честно)

- **Резервных копий пока нет** (аудит, №4) — в планах: Hetzner Backups + ночная копия базы на другой сервер.

- **Проверки сети видны получателю.** «Проверка портов» и «SSL» подключаются с IP сервера — в логах проверяемого сервера будет его адрес.
- **Сквозного шифрования нет.** Файлы и сообщения лежат на твоём сервере в открытом виде. Сервер твой, но если нужна полная секретность — это задача на будущее.
- **«📍 Место» отправляет точные координаты** — только по нажатию плитки, браузер спросит разрешение.
  Геолокация разрешена только нашему сайту (заголовок `Permissions-Policy`), чужие встроенные страницы её не получат.
- **Текст уведомления виден на экране блокировки** (как в мессенджерах). Не присылай себе пароли, если телефон лежит на виду.
- **Нет восстановления аккаунта.** Если очистить данные Chrome на телефоне, доступ к старым чатам пропадёт. Компьютеры нужно будет подключить заново, а старые чаты удалятся сами по срокам хранения.
- Файлы в чатах не проверяются антивирусом (только письма в «Проверке письма»). Не открывай присланные `.exe`, если не уверен в источнике.
- Нужен ровно один экземпляр приложения (живые соединения хранятся в памяти процесса).

## Как проверяется

Каждое правило выше закреплено автотестом в `tests/test_app.py`. CI запускает их на каждый push — если защита сломается, изменение не попадёт на сервер.
