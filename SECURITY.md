# Безопасность PhoneDrop

Простыми словами: что защищено, от чего и как.

## Как устроен доступ

Как в WhatsApp Web: **телефон — это аккаунт**, а компьютеры к нему подключаются по QR-коду.

| Кто | Чем доказывает, что это он | Где хранится |
|---|---|---|
| Телефон | Секретный ключ (256 бит) | Cookie `pd_phone`: HttpOnly, SameSite=Lax, Secure, 1 год |
| Компьютер 🏢 «чужой» | Свой секретный ключ (256 бит) | Cookie `pd_pc`: HttpOnly, SameSite=Strict, Secure. Живёт, пока открыт браузер |
| Компьютер 🏠 «мой» | Тот же ключ | Та же cookie, но на 90 дней (продлевается при каждом заходе) |
| QR-код | Одноразовый код подключения | Сгорает после сканирования, обновления страницы или через 5 минут |

- На сервере хранятся **только хэши** ключей (SHA-256). Даже если базу украдут, войти по ней нельзя.
- Секреты не попадают в адресную строку. Одноразовый код сразу убирается из адреса и становится бесполезным.
- Каждый компьютер видит **только свой** чат с телефоном. Рабочий ноутбук не видит переписку домашнего ПК.

## Хранение данных

| Что | Сколько хранится |
|---|---|
| Переписка с «чужим» компьютером | Удаляется через минуту после закрытия вкладки |
| Переписка с «моим» компьютером | Пока компьютер подключён |
| Файлы, фото, видео, голосовые | 30 дней (`FILE_TTL_DAYS`), потом удаляются. Текст сообщений остаётся |
| «Мой» компьютер, на который не заходили | Отключается через 90 дней (`REMEMBER_DAYS`) |
| Результаты «Инструментов» (сканы, PDF, сжатые фото) | 30 минут (`TOOL_TTL_MIN`), видны только тому, кто их сделал |
| Превью Word/Excel/PowerPoint | Пока лежит сам документ, удаляется вместе с ним |

Отключить любой компьютер можно в любой момент: на самом компьютере или с телефона (меню чата → «Отключить»). Вместе с ним удаляются переписка и файлы.

## От чего защищено

| Угроза | Пример | Защита |
|---|---|---|
| Кто-то сфотографировал QR-код | Коллега за спиной | Код одноразовый и живёт 5 минут. Новый компьютер виден в списке на телефоне |
| Забыл выйти на чужом компьютере | Ушёл с работы, вкладка открыта | Режим «чужой» по умолчанию + отключение компьютера с телефона |
| Перебор адресов чатов и файлов | Скрипт подбирает ссылки | Длинные случайные id (122–256 бит). Файл отдаётся только участникам своего чата |
| Вредный сайт шлёт запросы от твоего имени (CSRF) | Открыл ссылку, а она пишет в твой чат | Проверка `Origin`, обязательный заголовок `X-PD-Role`, SameSite-cookie |
| Скрипт в сообщении (XSS) | Прислали `<script>…</script>` | Текст выводится только как текст + строгая Content-Security-Policy |
| Опасный файл открывается в браузере | `evil.html` или `.svg` со скриптом | Такие файлы только скачиваются, плюс `CSP: sandbox` и `nosniff` |
| Имя файла `../../etc/passwd` | Попытка записать в системную папку | На диске файл лежит под случайным id, имя — только для показа |
| Встраивание в чужую страницу (clickjacking) | Невидимая рамка поверх кнопок | `X-Frame-Options: DENY`, `frame-ancestors 'none'` |
| Следы на чужом компьютере | Картинки в кэше браузера | `Cache-Control: no-store` |
| Переполнение диска | Загрузка гигабайтов мусора | Лимит 500 МБ на отправку, 4 ГБ на чат, проверка свободного места, срок хранения файлов |
| Спам | Скрипт создаёт тысячи подключений | Ограничение частоты по IP и по аккаунту |
| Вредный документ или «бомба» в фото | Word с эксплойтом, PNG на миллиард пикселей | Конвертер — отдельный контейнер: только внутренняя сеть без интернета, нет доступа к базе и файлам чатов, файловая система только для чтения, лимиты памяти/CPU/процессов, тайм-аут 2 минуты, проверка размера картинки до распаковки |
| PDF во встроенном просмотрщике | PDF со скриптом | PDF отдаётся без песочницы (иначе Chrome его не покажет), но с точным типом и `nosniff`: страницей сайта он стать не может, а скрипты PDF браузер выполняет отдельно от сайта |
| Чужие используют конвертер | Бесплатная «перегонка» файлов | Инструменты работают только для подключённого телефона или компьютера, ограничение частоты и размера (100 МБ) |
| Геолокация в фото | GPS в EXIF | «Сжать фото» удаляет все метаданные |
| Поддельные push-уведомления | Кто-то шлёт уведомления от имени сайта | Уведомления подписаны ключом VAPID сервера, содержимое шифруется для браузера |

## Что делается на сервере (при деплое)

- **HTTPS** с автоматическим сертификатом Let's Encrypt (Caddy) + HSTS.
- **Firewall** Hetzner: открыты только порты 22, 80, 443.
- Вход по SSH только по ключу, без паролей.
- Приложение в Docker-контейнере от обычного пользователя (не root), данные — в отдельном томе.
- Автоматические обновления безопасности Ubuntu.

## Чего пока нет (честно)

- **Сквозного шифрования нет.** Файлы и сообщения лежат на твоём сервере в открытом виде. Сервер твой, но если нужна полная секретность — это задача на будущее.
- **Текст уведомления виден на экране блокировки** (как в мессенджерах). Не присылай себе пароли, если телефон лежит на виду.
- **Нет восстановления аккаунта.** Если очистить данные Chrome на телефоне, доступ к старым чатам пропадёт. Компьютеры нужно будет подключить заново, а старые чаты удалятся сами по срокам хранения.
- Файлы не проверяются антивирусом. Не открывай присланные `.exe`, если не уверен в источнике.
- Нужен ровно один экземпляр приложения (живые соединения хранятся в памяти процесса).

## Как проверяется

Каждое правило выше закреплено автотестом в `tests/test_app.py`. CI запускает их на каждый push — если защита сломается, изменение не попадёт на сервер.
